## §1 体系优先序声明（最高裁决）

**裁决**：DGA 文档族（DGA / DGA-A / DGA-STRATEGY / DGA-MIGRATION / DGA-TOOLING）为本组织的**理论层与原则层 SSOT**——治理原则、组织形态学、判定语言的最终参照。原有全部文档（宪法 v2.4、GOVERNANCE.yaml、policy/ 11 件、ADR 序列、各仓 AGENTS.md）为**实施层**，与 DGA 文档族是**吸收并利用**关系。

**"吸收并利用"的四条语义**：

1. **吸收**：实施层条目逐条映射入 DGA 框架（absorption map，方向=**实施层条目 → 理论层条目**，IR-0007 产出）。映射完成后，实施层机制的权威来源=DGA 对应条款 + 本声明；
2. **利用**：运行中的执法机制**全额继续生效，不重写、不废弃**——它们是 DGA 形态学的活的实例化，且已经实弹验证（部分严于 DGA 目标：N-1/N-7、判定闭环、度量仪表）。重写运行中的执法机制违反验证经济学（已验证资产弃置=验证成本浪费）；
3. **冲突处理**：实施层与理论层冲突 → STRAT §8.3 断裂协议二选一。**举证责任在偏离方**：任何偏离 DGA 条款的实施层机制，必须以"合法实例采样"身份登记（参数差异+理由+登记位置）；未登记的偏离按理论层修正；
4. **新决策的推导顺序**：理论上从 DGA 出发 → 实例化落在实施层（新 ADR/机制/政策）。实施层新增机制必须在 absorption map 上可回链。

## §2 FR-01 裁决：考卷公开、答案密封、CNB 私有阵地

**裁决**（三阵地结构）：

1. **GitHub = 公开阵地（分发区）**。ADR-0020 全仓公开政策**不推翻、不变更**——20 仓维持公开，未来 GitHub 侧新仓默认公开。DGA 文档族入 GitHub 公开仓（狗粮公示的完全形态）；
2. **CNB = 私有阵地（真值区）**。新设 CNB 私有仓承载判定资产的**答案层**：holdout 的 golden 断言与判分逻辑、evalsets 的答案域、判分 rubric、未来的客户实例参数与私有 spec。公开侧（GitHub）仅保留 sealed 指针（sealed_sha256 引用纪律不变）——**考卷公开、答案密封**；
3. **灾备 = CNB 镜像 + Gitee 镜像**（§4）。

**裁决依据**（三条，入理论审议材料）：

- **威胁模型两层分解**：ADR-0019/0020 的"隔离不靠保密、靠可检测"针对的是 **agent 行为威胁**（本组织执行者违规读取）——可检测，检测式防线（诱饵、审计、挂载禁令）充分。公开仓面临的是**外部抽取威胁**（平台条款训练权、公开抓取）——不可检测，对不可检测的威胁唯一防线是真保密。两个威胁面不同，防线分层，互不否定；
- **判定基准折旧**：DGA §4.3——隐匿判定集以被学习为代价工作。golden 公开=该用例信息量永久归零；轮换律只能对冲增量，**不能复活存量**。答案层公开的持续代价是判定基准持续贬值，密封止血；
- **S5 决策**（2026-09-06）：维持公开的获客与公示价值 > 答案层保密的运维成本；私有阵地的运维面由 CNB 既有通道（token/审计工作流在用）最小化。

**对既有文件的效力**：

- ADR-0020：效力范围确认为 GitHub org，不变更；
- STRAT §5.4"eval 答案域、holdout、判例库、私有 spec 全文→永不出域"：**采样注记**——答案层不出域成立（迁 CNB 私有）；场景层公开=本组织的狗粮公示采样（护城河在积累过程不在条目，STRAT §1.2"模仿瓶颈从理解变为时间"）；登记于 STRATEGY v1.1 §5.4；
- 宪法 §10.1"接受 GitHub 单点残余"：被本裁决部分取代（灾备落地后残余收窄）。

**执行载体**：IR-0008 卡 B1/B2。**私有阵地 ADR**（编号顺延，约 ADR-0108）声明：阵地范围（什么可入、什么禁入——开发侧 agent 可读物禁入）、凭据分域（CNB 私有仓 token 不得进入开发侧计算池与 PM 上下文，INV-04 延伸）、DECISION-02 延伸（cloudbrid-agent 挂载禁令覆盖 CNB 私有仓）。

**诚实标注**：【待核】CNB 私有仓的免费配额与 API 权限细节未实测（T-03 调研时 CNB 仅作为镜像候选）。IR-0008 卡 B1 第一步=实测核验；若 CNB 私有仓不满足，**回退方案=阵地与镜像一对调**（Gitee 私有为阵地、CNB 为镜像一）——用户裁决的"CNB+Gitee"双平台结构不受影响，仅角色互换，重规划成本一次 PR。

## §3 FR-02 裁决：许可证

**裁决**：治理仓（.github、CI-Workflows、env-defs、archive、arbiter、holdout、template-service、cnb-bridge）**补 MIT 许可证**；产品仓维持现状（MIT/Apache-2.0 不变）；STRAT §5.4 AGPL 默认 → **采样注记**：宽松许可为本组织冷启动获客期的实例采样，AGPL 保留为理论默认；重审触发=出现"取实现改作托管竞品"行为，或治理线客户合同要求。

**执行载体**：IR-0007 卡 A6（每仓一个 LICENSE 文件 commit，一次 PR 逐仓）。

## §4 FR-03 裁决：灾备 = CNB 镜像 + Gitee 镜像

**裁决**：灾备区=CNB（公开内容明文镜像+私有阵地所在）+ Gitee（公开内容明文镜像+私有内容 age 密文 bundle 镜像）。地理/法域/运营主体独立性：GitHub↔CNB↔Gitee 三方互异，满足 TOOLING T-03 否决项①。

**镜像矩阵**：

| 内容 | 主存 | 镜像一 | 镜像二 |
|---|---|---|---|
| GitHub 公开仓内容 | GitHub（公开） | CNB 明文镜像 | Gitee 明文镜像 |
| 私有阵地内容 | CNB（私有） | ——（主存即镜像二） | Gitee age 密文 bundle |

**同步与对账**：weekly `git bundle --all` →（私有内容）age 加密 → push → 对账引擎逐平台校验（`git bundle verify`+大小/哈希对账，链断=红）→ evidence 账本落行。复用 GM-1 对账模式（pipefail/分通道/指纹去重/自动关四件套）。**季度恢复演练**：随机 bundle 解密重建裸仓+`git fsck`+抽样 blob 比对（MIG W2 门禁③思想）。

**执行载体**：IR-0008 卡 B3/B4/B5/B6/B7；试用期 spec 草案见选型证据 T-03/T-10（R-02/R-08 合并验收）。
