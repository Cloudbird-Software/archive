# ADR-0067: 恶意合规 adversary——judge-deep 锁定 + 套件不充分判定

- status: accepted（2026-08-22）
- deciders: 人（owner randypanding）+ AI
- 关联: 宪法 §4E（测试红队：恶意合规攻 AC 套件）/§4C、spec AC-5、AR-8
  （跨族分离）；.github#221（W4-C2）

## 背景

验收套件全绿不等于实现正确——可能只是存在"通过全部测试的最偷懒实现"：
硬编码期望值、对测试用例写特例分支、no-op 桩、永久缓存、忽略错误路径。
这类"恶意合规"（malicious compliance：形式上满足每条检查、实质上背叛
意图）是 §4E 测试红队的核心攻击对象。变异测试（§4A）测的是测试杀变异
能力，恶意合规 adversary 测的是套件对"针对性偷懒"的抵抗力——二者互补。
卡 #221 触发。

## 决策

1. **adversary 定义**：输入=spec+完整验收套件；输出=通过全部测试的
   最偷懒实现。攻击面清单版本化：硬编码期望/测试特例分支/no-op 桩/
   永久缓存/忽略错误路径（宪法 §4E 列举五类为初始集，可扩充走 C1）。
2. **判定语义（AC-1/AC-2）**：adversary 产物全绿 → 判"**套件不充分**"
   （blocking——实现 PR 阻塞，必须先补强套件：加变异/负控制/边界用例），
   报告标明钻的是哪个洞（对应套件缺口类型，供 test-author 定向补强）；
   adversary 攻击失败（无法全绿）→ 套件通过考验，但报告必须含 ≥1 条
   攻击尝试记录——防"恒绿 prompt"（adversary 假装攻击失败交白卷，让
   每个套件都轻松过关）。
3. **模型与 prompt 锁定（AC-3）**：adversary 用 judge-deep 档模型；
   模型+prompt 版本锁定并按 `judge_id@版本@prompt_hash` 存档（考试档案
   语义，与 ADR-0072 verifier 档案同构）——攻击结论可复现可审计。
4. **跨族分离（AR-8）**：adversary 模型族 ≠ builder 族 ≠ test-author 族
   ——同族攻击者与被攻击套件存在共谋面（同族共享盲区），族标记入 run
   元数据供 CI 断言。
5. **频率与成本**：spec PR 阶段 + 波次收口运行（非每 PR）；judge-deep
   档成本计入 BUDGET-01。
6. **误报通道**：合法实现形似偷懒（如确需缓存的场景）被判不充分 →
   needs-human 复核，人可裁决"套件充分+实现正当"并留判例记录。

## 后果

- 正面："最偷懒实现"成为套件质量的试金石；套件强度有了对抗背书而非
  覆盖率数字；钻洞归因让补强有的放矢。
- 负面/代价：judge-deep 档成本；偶发误报需人工复核；adversary 攻击
  报告本身是攻击知识库，需限制分发（红队报告区）。
- 风险与缓解：adversary 被弱化（喂过弱提示骗过锁定）→ prompt 版本
  锁定+审计+周演习（ADR-0069）可注入"应被判不充分"的弱套件样本；
  攻击面清单滞后 → 清单版本化，红队沉淀新洞回流。
- 回滚：adversary 关卡可退为抽样模式或摘除（套件质量退回依赖变异分数
  与负控制）；无状态迁移。
