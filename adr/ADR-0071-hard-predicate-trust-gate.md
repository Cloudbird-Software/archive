# ADR-0071: 硬谓词信任门 + shadow 域解锁（替代 risk-score）

- status: accepted（2026-08-22）
- deciders: 人（owner randypanding）+ AI
- 关联: 宪法 §5（信任演进：硬谓词白名单+shadow 域解锁）/§14 阈值、spec v4
  修订 1；.github#225（W5-C2）；废除对象=spec v3 risk-score 40（宪法明裁）；
  熔断沿用 ADR-0040；信任门策略落 arbiter capabilities.yaml（ADR-0054）

## 背景

spec v3 的 risk-score 标量把"未知"折叠成"安全"（分数不够高=需要人签，
分数不高不低=放行——但"没测过"与"测过没问题"同分）。宪法 §5 明裁废除，
改为**硬谓词白名单（fail-closed）+ 常设 shadow 模式**：准入是谓词清单
不是分数；域先 shadow（本应合并但不合并，与人裁决比对）积累 ≥50 例一致
才解锁自动合并。卡 #225 是该修订的实装卡。

## 决策

1. **准入谓词清单（全部可判定、fail-closed）**：合并的充要条件=
   全关卡绿 ∧ 证据齐全 ∧ 属于已解锁域。证据清单按域显式列举（测试
   记录/负控制/计量记录/揭封记录/负向控制…），清单版本化入
   governance/policy；**缺证据=拒绝，不是中性**（AC-1：无负控制记录的
   PR 拒绝合并——宁可错杀进人签，不可放过）。
2. **shadow 决策记录管线（AC-2）**：域未解锁时谓词判定照常运行——记录
   "本应合并/应拒绝"决策但不执行；与 owner 实际裁决比对，结果入 archive
   JSONL（§13 推论二飞轮原料）。
3. **解锁判据（AC-4）**：某域连续 ≥50 例 shadow 与人裁一致且零逃逸 →
   解锁（该域 PR 自动合并）；任何一例逃逸（shadow 说合、事后证明错）→
   计数重置归零。
4. **陷阱机制（AC-3）**：shadow 流混入 ≥10% 陷阱案例（已知应拒的 PR）；
   owner 放行陷阱 → 该域计数重置并记录——防 shadow 对齐退化为"人也被
   带着放行"。
5. **解锁后抽审**：已解锁域仍按 5% 随机抽人审（防解锁后漂移），抽样
   结果回流 shadow 比对。
6. **前三解锁域（宪法 §5 固定）**：① 无行为 diff 的整洁（格式化/注释/
   文档同步，AST 等价可证）；② 只增测试（不动产品代码，变异分必须升）；
   ③ 有 failing repro 的小修复（红→绿+负控制+只碰 repro 覆盖文件——
   全系统最强 oracle）。**明确排除、永远人签**：新功能实现、依赖升级、
   触及公开 API/schema/CI-Workflows 的改动。
7. **执法位置与熔断语义**：谓词判定入 arbiter capabilities.yaml 策略表
   （授权判定零 LLM）；成本熔断只准降级为人签，**不准降级为少验**
   （ADR-0040 变量复用，宪法 §5 原文条款化）。

## 后果

- 正面：自动合并从"分数够"变"证据全+域解锁"，每个放行可解释可回放；
  陷阱+抽审使解锁不是一锤子买卖。
- 负面/代价：shadow 期 4-8 周合并仍需人（宪法 §10.6 诚实接受）；每域
  ≥50 例的样本积累是时间成本。
- 风险与缓解：谓词清单有洞 → 陷阱机制+周演习（ADR-0069）持续攻击
   "本应拒却谓词全绿"的样本；shadow 比对数据被选择性记录 → JSONL
   append-only 入 archive。
- 回滚：未解锁域 shadow 无合并权——整体退回全人签零损失；已解锁域可
   一键回锁（域状态是策略表条目）。
