# ADR-0069: 活体演习链路——周种子缺陷注入 + 诱饵联动 + 缺席 fail-closed 演练

- status: accepted（2026-08-22）
- deciders: 人（owner randypanding）+ AI
- 关联: 宪法 §4B（每周种子缺陷注入——安全论证唯一的活体证明）/§6（缺席
  fail-closed）；.github#223（W4-C4）；缺席停自动合并先例 #180、ADR-0057
  dead-man 心跳；诱饵=ADR-0056（W1-C4）

## 背景

关卡可能"存在但死了"——永远绿的关卡与没有关卡等效，而静态检查（配置
存在、语法正确）无法证明关卡活着。宪法 §4B 把活体演习定为"整个安全论证
唯一的活体证明"：每周向随机 PR 注入已知缺陷，验证关卡真的会变红。§6
同理：缺席 fail-closed（审计包/心跳缺席→自动合并自动关闭）不能只在设计
文档里成立，必须周期性实测。卡 #223 触发组链。

## 决策

1. **缺陷样本库**：每条样本含缺陷内容、预期触发的关卡 ID、难度标注；
   **owner 逐条审批**后才入库（AC-2）；样本库 owner 直管，不入 agent
   可读路径——防 agent 学会样本特征后针对性放行。
2. **周演习（AC-1）**：每周从样本库随机选取，向随机选中的 PR 注入
   （注入由**独立 workflow** 执行——非关卡建设者，被审者不能组织对
   自己的审计）；验证"该缺陷应触发关卡 X 失败"。
3. **红绿判定与公开**：关卡变红=演习成功；关卡绿=**演习失败** → P0
   issue + 该关卡标 suspect；演习红/绿记录进 dashboard 公开；红率应
   ≈100%，偏离即关卡失效告警（AC-4）。
4. **Goodhart 防护**：样本难度趋势有记录（AC-4）——防"为演习写代码"
   （关卡只学会抓样本库内的缺陷类型，对真实缺陷失明）；样本轮换与
   扩充是 owner 月度 holdout 补给职责的组成部分（宪法 §2）。
5. **诱饵联动**：holdout 泄漏诱饵检查（W1-C4 部署）并入周演习——诱饵
   内容出现于任何 agent 上下文/日志即报警（§6）。
6. **缺席 fail-closed 全链路演练（AC-3）**：人为暂停审计包/心跳 →
   缺席超时 → 自动合并自动关闭——已有 #180 先例，本卡将其纳入周期
   回归（每季至少一次实测），结果记录进演习台账。

## 后果

- 正面：安全论证从"声明"变"活体证明"；关卡失灵在演习性红而非真实
  逃逸中暴露；缺席降级机制保持"被实测过"状态。
- 负面/代价：每周注入消耗 Actions/LLM 预算+演习失败的归因人力；注入
  PR 对不知情围观者是噪音（演习记录公开可查缓解）。
- 风险与缓解：注入样本被 agent 吸收进上下文 → 注入在隔离分支/独立
  run 执行，不进 agent 工作区；演习本身被 Goodhart（挑简单样本）→
  随机选取+难度趋势记录+owner 审库。
- 回滚：演习 workflow 摘除即停，无状态残留（台账 append-only 留档
  无害）；缺席演练可单独停用。
