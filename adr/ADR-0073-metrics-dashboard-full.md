# ADR-0073: 度量 dashboard 完整版——北极星对同屏 + 四类指标 + 板字段

- status: accepted（2026-08-22）
- deciders: 人（owner randypanding）+ AI
- 关联: 宪法 §8（度量全景）/§12（状态可视化三投影）、§7（反退化）；
  .github#227（W5-C4）；骨架沿用 ADR-0055（W1-C3 dashboard 账本）、
  ADR-0057（15min 账本刷新 cron）；SLI 口径沿用 ADR-0059

## 背景

宪法 §8 的北极星是一个**指标对**而非单一指标：每周零人类接触合并数 ×
质量护栏（逃逸率/回滚率/holdout 与主套件通过率差）不劣化。若合并数单独
上屏，Goodhart 定律保证系统会优化合并数牺牲质量。W1-C3 已落 dashboard
账本骨架（issue 双区结构+15min 刷新）；W5-C4 补全四类指标、北极星对
互锁与 Project 板字段。卡面触发：北极星对必须**同屏实时**，质量劣化时
合并数自动归零显示。

## 决策

1. **北极星对同屏互锁（AC-1）**：零人类接触合并数与质量护栏同屏实时；
   护栏任一劣化超阈（逃逸率>0 持续、回滚率超阈、通过率差超 5%）→
   **合并数显示自动归零**——不是隐藏是显式归零（劣化期间的产出计数
   无意义），恢复条件=护栏回绿。
2. **注意力会计（AC-2）**：owner 签署耗时（宪法 §7：如实计入判断预算，
   防"签署退化成隐形 review"）、needs-human p90（超 1 天=整机停摆，
   单独显示不洗白）、每合并 owner 分钟、超时默认触发数、可疑快速签署数
   （签署耗时低于阈值视为退化信号计数）、周审计超时率。
3. **安全正确性（AC-2）**：仲裁误放行/误拒数（arbiter 台账源）、未经
   仲裁的状态变更泄漏数、种子缺陷演习红率（应≈100%，源=ADR-0069）、
   陷阱拦截率（源=ADR-0071）。
4. **成本（AC-2）**：单 IR 美元（硬上限+熔断）、管家美元/周、patrol
   yield（每百次唯一真 bug 数，源=ADR-0065）；数据源=计量 wrapper
   归账（ADR-0062）。
5. **Project 板字段完善（AC-3）**：factory-floor 只读投影板字段=
   卡 ID/AC 进度/关卡状态/认领者/停留时长/谓词状态；label 唯一真相源，
   板为投影，同步每 15min，漂移报警（§12，ADR-0055 机制延续）。
6. **用户结果指标（AC-4）**：每产品至少一个用户侧结果指标进 dashboard
   （防产品漂向"oracle 友好型"，宪法 §8）；季度难测产品/功能配额有
   记录位（配额制——刻意做一个难测的，防工厂只做容易验证的）。
7. **诚实显示纪律**：数据源缺失的指标显示 `pending` 不显示 0——
   "缺数据"不得被渲染成"好数据"（ADR-0059 先例：零合并周输出 N/A）。

## 后果

- 正面：owner 一屏见全局且无法被单一指标欺骗；注意力成本可见（判断
  不可压缩的量化面）；四类指标各有上游数据源，非手工填报。
- 负面/代价：指标采集面广——各产品仓需按 blastRadius 声明指标埋点，
  埋点滞后则长期 pending；15min 刷新的 API 配额消耗。
- 风险与缓解：dashboard 自身被 Goodhart → 北极星对互锁+周审计 owner
   从原始事件日志独立复算（§7，不信管家组装的包）；投影与 label 漂移
   → 报警机制（AC-3）。
- 回滚：dashboard 是投影层，摘除更新脚本即回 W1 骨架；无数据损失
   （原始事件日志仍在）。
